别再手写 commit log 了
一句话，生成大厂标准的提交记录

gcm 读取项目的 git diff，交给 AI 按 Conventional Commits（Angular 规范）生成 标题 + 正文 + 两条备选，确认后一键提交。支持接入 WorkBuddy 的 MCP 模式，零 API Key、零成本。

01

同一个改动，两种提交记录

评审时被问“这个 commit 到底改了什么”的尴尬，大多来自随手写的 message。

✗ 随手写（无法回溯、无法生成 CHANGELOG）

update

改了点东西
修复bug
再改一下

# 问题：type 缺失 / 描述含糊 /
# 一条 commit 混了多个变更

✓ gcm 生成（符合 Angular 规范）

fix(auth): 修复 token 过期后刷新失败的问题

旧逻辑在 token 过期时直接抛出 401，未触发
refresh 流程，导致用户被强制登出。

现在过期前 60 秒主动刷新，刷新失败才登出。
补充 refresh 过期场景的单测。

05
三种用法，按习惯挑一个

    
同一套规范内核，三种入口：对话里用、网页上点、终端里敲。

    

      

        
MCP 接入零成本

        
挂进 WorkBuddy，AI 自带能力生成，不需要任何 API Key。

        
帮我把 D:/code/app 的改动提交

      

      

        
网页版

        
双击 start.bat 自动开页面，选项目 → 生成 → 点提交。

        
start.bat → localhost:7788

      

      

        
命令行

        
接任意 OpenAI 兼容模型，适合脚本化与终端党。

        
node gcm.js D:/code/app --commit

      

    

  


  

    
06
它是怎么工作的

    
不猜、不编：所有结论都来自真实 diff。

    

      

        
读取变更
git diff

        
识别规范
Conventional Commits

        
生成候选
1 推荐 + 2 备选

        
落地方式
git commit -m

      

      

        
MCP 工具作用

        
          
get_changes读分支、diff、未跟踪文件，并返回规范生成要求给 AI

          
commit用确认后的 message 提交暂存区变更

          
stage_allgit add -A，连暂存步骤一起省掉

        
      

    

  


  

    
07
给谁用

    
写代码的人每天至少遇到一次的场景。

    

      

        
个人开发者

        
提交前 3 秒生成规范 message，历史记录从此能当文档看，做 side project 也不再写“update”。

      

      

        
团队 / 开源维护者

        
统一规范不靠人盯：review 时不必再纠正措辞，CHANGELOG 与 semantic-release 直接可用。
